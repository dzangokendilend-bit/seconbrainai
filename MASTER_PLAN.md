## 1. Видение продукта

**Моника** — веб-сервис «личного ИИ-пространства»: закрытая бета для друзей,
в будущем публичный продукт. Один спокойный тёмный интерфейс, где пользователь:

- общается с Моникой в чате (выбор моделей, стриминг, сессии с историей);
- работает с личными заметками через **Терминал** (дерево vault + md-редактор
  + журнал изменений с откатом);
- ведёт **личную Википедию**, которая автогенерируется из заметок в эстетике Иванопедии;
- подключает модули: Википедия-поиск, Telegram-бот, Полная аналитика (гейт 4221);
- управляет аккаунтом: ключи API, модели, аватар, юзернейм, пароль.

### Принципы (не нарушать)
- Стек: **Python stdlib + vanilla JS/CSS**. Никаких фреймворков, сборщиков,
  библиотек редакторов/анимаций.
- Дизайн: только эстетика **Сибериады/Иванопедии** (`style.css` — источник 1:1:
  стекло, aurora, серифы Montserrat/Inter, токены `:root`).
- Безопасность: ключи шифрованы машинным секретом (`app/keys.py`), изоляция
  пользователей на сервере, терминал не выходит за vault (`safe_path`),
  единственное удаление в системе — undo созданного терминалом файла.
- Дисциплина агента: тестовые файлы только в `tmp/` (удалять после), план перед
  крупными правками, smoke после каждого коммита, один логический коммит на подфазу.
- **Авто-ОК отключён**: каждая подфаза → отчёт → визуальная проверка автора → ОК.

| `history.py` | history.jsonl (лимит 500), record/recent/undo |
| `modules.py` | поиск, выжимки, аналитика, вики-очередь + generate_article (smart-модель) |
| `tgbot.py` | per-user TG-поллер |

`/api/*`: me, login, logout, check-username, hint, onboarding/complete, models,
prefs/model, keys (+check), profile/username|avatar|password, key-check, modules,
analytics/check|summary, chat, chat/stream, terminal, terminal/execute,
vault/tree|read|write|history|undo, wiki/search|extract|articles|regen, tg/setup|status.

### Frontend (app/web/)
- `index.html` — 3 экрана: scr-login / scr-wizard / scr-app (`.cs-page`).
- `app.js` (~1100 строк) — рендер всех экранов, состояние (ME, TAB, CHAT_HIST, SESS, TERM, W, CFGM).
- `style.css` — дизайн-система Иванопедии (не трогать), `monica.css` — Моника-специфика.
- `tools/ui_smoke.js` — 58 проверок, запуск: `node tools\ui_smoke.js`.

### Данные (data/)
`users/index.json`, `users/<uid>/{profile.json, keys.enc, avatar.*, vault/, history.jsonl, wiki_queue.json}`,
`sessions/sessions.json`. Сессии чата — **localStorage** фронта (ключ `monica_sess_<username>`).

## 6. Спецификации задач (13 пунктов автора)

### 6.1. Настройки пользователя — ✅ база есть, дожать
Есть: смена юзернейма/аватара/пароля, ключи с проверкой живости, модели, модули.
Доделать: статус-индикаторы ключей цветом (валиден/ошибка/не проверялся) уже частично;
добавить отображение даты создания аккаунта, «экспорт данных» (идея, §8.1).

### 6.2. Вступительный этап (онбординг 2.0)
- Полноценный «презентационный» шаг 0–1: полноэкранный hero-слайдер (3–4 слайда:
  что такое Моника → возможности (чат/терминал/вики/модули) → закрытая бета),
  автопрокрутка + точки-индикаторы, кнопка «Начать».
- Анимации появления карточек возможностей (stagger fade), без библиотек.
- Примеры: мини-скриншоты/мокапы возможностей (статичные, в стекле).

### 6.3. Медиа: фото/видео/файлы/голос — реверс Сибериады (изучено)
**Как это устроено в `second-brain/tools/chat_server.py`:**
1. **Аудио/голос** → `transcribe_audio(audio_b64, mime)`: multipart POST в
   Groq Whisper (`/audio/transcriptions`, модель whisper), текст → обычный чат.
2. **Видео** → `extract_video_frames(bytes, 3)`: ffmpeg извлекает 3 JPEG-кадра
   равномерно по длительности → кадры как `image_url` (data:image/jpeg;base64)
   в vision-модель через OpenRouter; аудиодорожка видео → Whisper.
3. **Файлы** → `save_attachment(name, data_b64)` → папка «07 Attachments»,
   до 5 файлов на сообщение; маршрутизация по mime/расширению:
   изображение → vision, видео → кадры+транскрипт, аудио → Whisper, остальное → сохранение.
4. Фронт: слоты «+» в композере, FileReader → base64 → JSON в /api/chat.

**Порт в Монику (план):**
- `app/media.py`: transcribe (Groq Whisper), extract_frames (ffmpeg), save_attachment
  → `data/users/<uid>/attachments/`, mime-маршрутизатор `analyze_attachment()`.
- `/api/chat` принимает `files: [{name, data, mime}]` (до 5), `/api/chat/stream` тоже.
- Композер: слоты 🖼/📎 активируются, превью вложений перед отправкой.
- Зависимости: ключ Groq (новый сервис в реестре ключей), ffmpeg в PATH (проверять при старте).
- Ограничения: размер вложения ≤ 10 МБ, только текстовые модели видят текст файлов.

### 6.4. Возврат на главную из онбординга
Кнопка «← Назад» на шаге 1 визарда → `renderLogin()`. Тривиально.

### 6.10. Сессии: дата начала
В записи сессии хранить `started` (ISO) — показывать в списке и в шапке чата
«сессия начата 28 августа, 14:02». Сохраняется в localStorage вместе с сессией.

### 6.11. Закрепление чатов
Флаг `pinned` у сессии; закреплённые — сверху списка с иконкой 📌; сортировка:
pinned → по времени. Клик по 📌 — открепить.

### 6.12. Проекты в сессиях
Сущность «проект»: {id, name, emoji/logo (dataURL), background (градиент/цвет из
палитры), sessionIds[]}. В боковой панели — секция «Проекты»: создание, назначение
сессии в проект (контекстное меню сессии), фильтр списка по проекту, у сессии
бейдж проекта. Хранение — localStorage (как сессии). Фон проекта может подсвечивать
шапку чата.

### 6.13. Мигание при переключении сессий
Причина: `openSess` вызывает `openTab("chat")` → `tabChat` рендерит пустой чат +
анимация `.tab-in`, затем сообщения дорисовываются. Фикс: в `openSess` рендерить
чат напрямую без анимации (флаг `skipAnim`), либо сначала заполнить лог, потом
показывать. Анимация `.tab-in` — только при смене модуля, не при смене сессии.

### 6.14. Редактор терминала — больше
`.te-wrap` flex:1 уже растёт; увеличить за счёт: уменьшить tmid-switch до тонкой
полосы, chat-лог терминала и дерево не должны съедать высоту; min-height редактора
60% панели; соседние панели (дерево/изменения) — уже разнесены. Дочистить отступы.

## 8. Идеи по улучшению (ждут одобрения автора — БЕЗ ОК НЕ ДЕЛАТЬ)

### 8.1. Настройки
- **Идея: «Экспорт данных»** — кнопка «скачать мой vault + профиль zip». Плюсы: доверие, бэкап. Минусы: объём работы (zip на stdlib — есть `zipfile`), средняя.
- **Идея: индикатор силы пароля** при смене. Плюсы: UX. Минусы: нет.
- **Одобрение Автора:** Пока что нет

### 8.2. Онбординг
- **Идея: интерактивное демо чата на слайде возможностей** (мини-мок с заранее
  записанным диалогом, «печатается» на глазах). Плюсы: вау-эффект. Минусы: +1 экран сложности.
- **Идея: пропуск онбординга с дозаполнением позже** (кнопка «Настроить потом»,
  ключи можно ввести после). Плюсы: меньше трения. Минусы: часть функций не заработает
  без ключей — нужно честное предупреждение.
  
- **Одобрение Автора:** Да

### 8.3. Медиа
- **Идея: голосовой ввод с микрофона** (MediaRecorder → Whisper) — в Сибериаде уже
  был `.cs-mic`. Плюсы: сильная фича, код частично есть. Минусы: разрешения браузера.
- **Идея: OCR для изображений без vision-модели** — нет, лучше сразу vision через OpenRouter.
- **Идея: галерея вложений пользователя** (все файлы в одном месте). Плюсы: порядок. Минусы: ещё одна вкладка.

- **Одобрение Автора:** Да

### 8.4. Возврат на главную
- **Идея: черновик онбординга** (W-стейт в localStorage) — вернулся и продолжил с того же шага. Плюсы: UX. Минусы: чуть больше состояния.
- **Одобрение Автора:** Да


### 8.5. Подсказка пароля
- **Идея: после 5 неудач — ссылка «сбросить пароль» через секретный вопрос/код автору.** Плюсы: self-service. Минусы: нужен механизм сброса (бэкенд) — отдельное согласование.
- **Одобрение Автора:** Да


### 8.6. Терминал
- **Идея: diff-просмотр перед откатом** (показать, что изменит undo). Плюсы: безопасность. Минусы: средняя сложность.
- **Идея: markdown-превью в редакторе** (Редактор ⇄ Превью). Плюсы: наглядность. Минусы: md()-рендер уже есть — дёшево.
- **Идея: drag&drop файла в редактор из дерева.** Плюсы: удобно. Минусы: низкий приоритет.
- **Идея: терминальные «рецепты»** — библиотека готовых запросов к ИИ (наведи порядок, сгруппируй заметки). Плюсы: показывает силу. Минусы: контент.
- **Одобрение Автора:** Да


### 8.7. Вики
- **Идея: «Случайная статья» и «Ссылки сюда»** как в Иванопедии. Плюсы: аутентичность. Минусы: нужны обратные ссылки (парсинг `[[...]]`).
- **Идея: ручное редактирование статей вики** (через тот же редактор терминала). Плюсы: контроль. Минусы: риск рассинхрона с заметкой-источником.
- **Одобрение Автора:** Да


### 8.8. Баннер
