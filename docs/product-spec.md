# Моника 1.0 — продуктовая спецификация нового этапа (Фаза 0 → Фаза 9+)

> Статус: черновик Фазы 0 (аудит и планирование). Дата: 2026-08-31.
> Источники: промпт-видение автора, ROADMAP.md, AGENT_PLAN_MONICA.md, аудит кода
> Моники (`app/*.py`, `app/web/`) и Сибериады (`vajga/second-brain/tools/`).
> Стек менять нельзя: Python stdlib + vanilla JS. Файлы JSON — ок. Без Docker/БД-серверов.

## 1. Позиционирование

Моника — веб-сервис «личного ИИ-пространства»: закрытая бета для друзей с прицелом
на публичный продукт. Новый этап превращает Монику из «чата + терминала + вики» в
**личный second-brain с ассистентом**: импорт существующего хранилища знаний,
прозрачный процесс ответа с источниками, дневные бюджеты, совместные проекты и
честная телеметрия.

Принципы, которые не меняются (из ROADMAP.md):
- Python stdlib + vanilla JS, никаких фреймворков.
- Дизайн-система Сибериады/Иванопедии (стекло, aurora, серифы) сохраняется.
- Изоляция пользователей на сервере; терминал не выходит за vault.
- После каждого этапа — `node tools/ui_smoke.js` 76/76 (и расширение тестов).

## 2. Персоны и сценарии

- **Иван (автор, первый боевой пользователь)** — импортирует свой Obsidian-vault
  (second-brain), пользуется чатом с доступом к хранилищу, Telegram-ботом Luna,
  аналитикой.
- **Друг-тестировщик (закрытая бета)** — заводит аккаунт через онбординг, ведёт
  заметки, общается с Моникой, возможно приглашается в совместный проект.
- **Будущий публичный пользователь** — те же сценарии, но с самостоятельной
  регистрацией, лимитами и телеметрией.

Ключевые сценарии нового этапа:
1. «Перенеси мой Obsidian в Монику» — мастер импорта с preview и отчётом.
2. «Спроси что-то по моим заметкам / по интернету» — композер с 3 режимами,
   ответ с этапами процесса и цитатами-источниками.
3. «Прикрепи фото/файл/заметку» — единая кнопка вложений (объединение слотов
   6-M и заметок из vault).
4. «Не дай мне сжечь лимиты» — дневной бюджет токенов, статусы ключей.
5. «Покажи, как я работал(а) за год» — heatmap-аналитика с re-auth.
6. «Поработай со мной над проектом вместе с другом» — совместные проекты (RBAC).

## 3. Функциональные блоки

### 3.1 Импорт Obsidian / second brain (мастер)
- Источники: локальная папка, ZIP-архив, отдельные .md.
- Разбор frontmatter (title/created/tags), `[[wikilinks]]` → внутренние ссылки
  Моники, вложения из папки вида `07 Attachments`.
- Preview до записи: дерево «что импортируется», конфликты, дубли по checksum
  (sha256 содержимого).
- Стратегии конфликтов: skip / overwrite / rename (N-суффикс).
- Фоновая идемпотентная задача (очередь заданий на сервере, статус в UI,
  повторный запуск не создаёт дублей).
- Экспорт vault обратно (zip) — база уже есть: `/api/profile/export`.

### 3.2 Аналитика
- Heatmap за год (стиль Сибериады `calendar_heatmap_svg`): метрики — заметки
  (mtime/создание в vault), сообщения чата (history.jsonl), сессии.
- Фильтры по метрике, выбор часового пояса пользователя (из онбординга).
- Расширенная аналитика: вместо пароля `4221` — **re-auth** (повторный ввод
  своего пароля, сервер ставит краткоживущий флаг сессии).
- Ночная обработка `daily_knowledge_digest`: идемпотентная задача (ключ = дата),
  создаёт inbox-заметки с provenance (источник, время, модель), история запусков
  в `data/users/<uid>/jobs/`, ручной backfill за пропущенные дни.

### 3.3 Telegram (Luna)
- Панель привязки: одноразовый код (6 цифр, TTL 10 мин) вместо ручного ввода
  chat_id; бот подтверждает привязку.
- Права бота: что можно (читать vault, писать заметки, слать проактивные) —
  чекбоксы в настройках.
- Кастомные команды: декларативные (название + промпт + действие), allowlist
  операций, dry-run режим.
- Инициативные сообщения: opt-in, quiet hours, шанс — **порт из Сибериады**
  (`_proactive_loop`, `/proactive on|off|hours|chance`).
- Библиотека стикеров: file_id, описание/настроения, вес, cooldown — **порт из
  Сибериады** (`stickers.json`, `pick_sticker`, `handle_incoming_sticker`).

### 3.4 Провайдеры и проверка ключей
- Расширение `providers.ping()`: состояния `ok / quota / permissions /
  unavailable / unverified` (разбор 429/401/403/5xx), маскирование сохраняется.
- Отображение в настройках цветом + текстом последней проверки.

### 3.5 Антивандальная защита
- Rate limits на маршруты (простой in-memory счётчик per-IP+uid).
- Дневные лимиты токенов: настройки (лимит, период), использовано/осталось,
  **атомарное резервирование** перед запросом к LLM (файл-блокировка +
  запись расхода после ответа), разбивка по моделям.
- Audit log: `data/users/<uid>/audit.jsonl` (входы, смены пароля, записи в
  vault, экспорты, смена ключей) — append-only, маскированные значения.
- Изоляция: уже есть (uid в путях), добавить тесты на попытку доступа к чужому
  vault/профилю.
- Prompt injection: системная инструкция + экранирование содержимого заметок
  при подаче в контекст (маркер «данные, не инструкции»).
- Soft delete: удаление заметок/сессий → `trash/` с TTL, вместо физического
  удаления (кроме undo терминала — остаётся как было).

### 3.6 Совместные проекты
- Серверная сущность «проект» (сейчас проекты сессий — localStorage).
- Приглашения по одноразовому коду/ссылке; роли owner/admin/editor/member/viewer.
- Общий чат проекта (отдельная history), version history заметок проекта
  (снапшоты в `history.jsonl` проекта), presence (кто онлайн — heartbeat).
- MVP: общие заметки + чат; presence и одновременное редактирование — позже.

### 3.7 Веб-поиск и режимы композера
- 3 режима у композера: обычный / по хранилищу / в сети.
- `SearchProvider` interface (stdlib): SerpAPI-адаптер **порт из Сибериады**
  (`tool_web_search`), плюс заглушка «по хранилищу» через vault-индекс.
- Пайплайн research: запросы → кандидаты → извлечение текста → дедуп → синтез
  с inline citations `[1]`… и списком источников.
- Режим документа: outline → черновик по секциям (использует smart-модель).

### 3.8 Прозрачный процесс ответа
- Статус-строка этапов над ответом (ищу в хранилище / в сети / читаю / пишу).
- Панель «Process»: этапы, время каждого, источники. Без system prompt и
  reasoning. Данные собирает сервер в `trace` (паттерн `trace` из Сибериады).

### 3.9 Вложения 2.0
- Единая кнопка «Прикрепить»: фото/файл (слоты 6-M уже есть) + **заметка из
  vault** (новый тип слота).
- Drag-and-drop и clipboard paste — уже частично есть в композере, добить
  MIME-проверку и лимиты в одном месте (`media.py`).

### 3.10 Лимиты токенов (UI)
- Настройки: дневной лимит, разбивка по моделям (light/smart), использовано
  сегодня / осталось, сброс в полночь по часовому поясу пользователя.
- Сервер — единственный источник истины; клиент только отображает.

### 3.11 Телеметрия
- Минимальная агрегированная (счётчики событий, без контента) — по умолчанию on.
- Opt-in для контентных данных (анонимизированные примеры диалогов).
- Экран прозрачности в настройках: что собирается, зачем, как выключить.
- Product Insights: еженедельная сводка → заметка в `vault/Monica/Ideas/`.

### 3.12 Браузерное расширение (опционально, последняя фаза)
- Ручное сохранение страницы/выделения в vault (Manifest V3, fetch к API
  Моники с токеном), allowlist доменов, нормализация URL (убрать utm_*).

### 3.13 UX и доступность
- Сохранить дизайн-систему; все новые экраны имеют loading/empty/error
  состояния; `prefers-reduced-motion` (уже есть в онбординге) — везде.

## 4. Не входит в этот этап
- Полная аналитика «Око» (наблюдение за другими людьми) — остаётся выключенной
  по этическим соображениям.
- Реалтайм-совместное редактирование (OT/CRDT) — только снапшоты.
- Облачная инфраструктура, очереди сообщений, БД-серверы.

## 5. Критерии приёмки этапа
- Все функции из таблицы в `implementation-plan.md` доведены до своих фаз.
- `ui_smoke.js` расширен и зелёный (≥76, фактически больше) после каждого коммита.
- Импорт реального vault Ивана проходит без дублей и потерь (checksum-отчёт).
- Дневной бюджет реально останавливает перерасход (тест с mock_llm).
- Совместный проект: два аккаунта, роли, приглашение, общая заметка с историей.
